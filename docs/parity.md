# Parity methodology and report

## Reference

- Upstream: `eschrom/SPACE`
- Commit: `94f0a0f9311e2ee2b406ebc45c84a4e93f2f38f8`
- Default numeric tolerance: `1e-10`
- Iterative/BLAS-dependent tolerance: at most `1e-8`, only with a reason in the
  individual test

Live tests use a pristine temporary checkout or a caller-supplied checkout that
must match the commit and have an empty Git status. Oracles are generated by R
at test time. The committed synthetic fixtures carry SHA-256 checksums and are
regenerated by `scripts/generate_core_parity_oracles.R`.

## What is compared

The API-surface test maps all 24 R exports. Behavior tests cover those exports
and output-affecting internals: distribution construction and smoothing,
entropy, R rounding, patch summaries, random census construction, cisMI,
transMI, table/image census, pattern learning/mapping, diversity, merging,
volume calculations, loaders, parameter suggestions, palettes, and plot data.

Comparisons include column names, order, categories, counts, warnings/errors,
and numeric results. Plot tests compare encoded tables, labels, scales, and
saved artifacts rather than pixels.

## Current local result

The release report is refreshed by `make parity`. At the time this source tree
was assembled, both live-R test cases and the complete static parity suite
passed against the pinned pristine checkout. Exact commands and current results
are recorded in `RELEASE_VERIFICATION.md` at handoff; that file is not a
substitute for rerunning the checks in a new environment.

## Known boundary

Python integer seeds are stable within PySpace, not guaranteed to reproduce R's
generator. Cross-language randomized comparisons use explicit seed points,
bootstrap inputs, permutations, or SOM initialization/order plans. The
within-column cisMI permutation fallback is exploratory and labels its
provenance; it never silently replaces the SPACE patch-randomization model.
